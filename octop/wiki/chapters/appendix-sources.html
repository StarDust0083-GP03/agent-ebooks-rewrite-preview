术语速查#

术语 在本书中的意思
宿主 把运行库接成产品的 Octop 服务
控制面 用户、资源、配置与权限等持久状态
composition root 集中创建并连接依赖的位置
turn 一次处理回合，不等于一条 token 帧
session_key 某个入口绑定当前线程的会话键
thread_id 持续对话及执行状态的身份
checkpoint 运行图保存与恢复的状态
projection 为某种读取需求形成的消息视图
HITL 工具执行前后的人工参与与恢复机制
inbox 多 Agent 派工和回叫的内部协调入口
outbox 本章教学模型里的待投递记录，不表示已发送
Bridge Octop 实例间请求与流的桥接
MCP 工具发现与调用协议，不是权限模型
ACP Agent 与客户端或 runner 的交互协议

先读哪五组材料#

  1. 起点：docs/architecture.md 与 infra/server.py。 文档建立地图，代码核对实际单例与装配顺序。
  2. 决策：ADR 001 与 ADR 002。 结合阅读，区分最初的 SQLite 背景和后来加入的 PG 选择。
  3. 主链路：chat/ws.py、chat/turn.py 与 GlobalProcessor。 跟踪身份、绑定、排队、执行、记录和推送。
  4. 存储：docs/versioned-history.md、db/pool.py 与 history/。 先列保证和非目标，再读事务与恢复。
  5. 协作：docs/expert-teams.md 与 teams/jobs.py。 不要将早期 mailbox 设计全文当作新实现清单。

参考本地 SAM 系列的方法#

本书按用户要求参考本地 learning_sam 的系列博客组织方式。主要对照材料包括支付系列开篇、需求 PRD、技术方案、支付编排与渠道路由，秒杀系列幂等设计，以及 DDD 工程目录划分。它们用于研究如何讲解，不用于证明 Octop 的实现。

借鉴点是需求推导、职责边界、关键代码、完整场景和异常闭环。本文没有复制原博客正文、图片、生产事故和性能指标，也没有把第三方全文归档放入电子书。SAM 材料本身的实现或数字是否可靠不属于本次研究范围。

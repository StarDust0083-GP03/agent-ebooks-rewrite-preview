代码实战：用最小宿主验证四条边界

源码快照 2026-10-27 · 约 8 分钟

不做一个假的 Octop#

前面的代码入口分布在宿主、运行库和前端，第一次阅读容易只记住类名。本章把四条边界压成一个标准库程序：共享专家不共享私人线程、入口可以改绑、批准绑定已保存的参数、重复批准不重复创建待投递记录。

程序位于 examples/mini_host.py，测试位于 examples/test_mini_host.py。它不是 Octop API，不调用真实模型，不启动 WebSocket，不发送邮件，也没有实现项目的 Team 或 Memory。用户整数由测试可信地提供，不能用作真实登录方案。

数据模型先于接口#

最小模型有五张表：agents 管专家所有者与分享标志；threads 管用户与专家下的私人对话；sessions 管入口到当前线程的绑定；actions 保存待审批内容及状态；outbox 保存批准后的待投递记录。

关键不在表数，而在两个关系：session 指向 thread，不拥有 thread 的全部生命周期；outbox 以 action 为主键，同一个审批动作只能产生一条待投递记录。

所有表都在一个 SQLite 库里，是为了能用一个事务展示本地原子性。它刻意避开 Octop 多层存储和外部网络，不能用这个实验推导生产系统也具有同样的事务范围。

共享专家时仍检查 thread#

程序先检查用户是否可用专家，再核对线程里的 user 和 agent。对共享专家的访问允许周越建立自己的线程，却不能让他借用林岚的 thread_id。

host.add_agent("research", 7, shared=True)
lin = host.open_thread(7, "research")
zhou = host.open_thread(9, "research")
assert lin != zhou

open_thread 的 session key 在服务端根据可信 user 和 agent 生成，不让模型任意选择另一个用户的身份。fresh=True 切换当前入口的绑定，但旧线程仍在，可通过正确身份读取。

这对应第五章的身份边界，而不是模拟完整用户组或管理员模型。

批准时不要重新接受一份待发送正文#

propose 先保存收件人与正文，得到 action_id。approve 接收身份、线程与 action_id，不重新接收一个可被替换的 recipient。

这样批准针对的是已保存内容。真实系统仍要考虑审批展示是否与内容一致、动作有效期和参数编辑流程；这个模型只展示最小绑定关系。

程序中的条件更新是：

UPDATE actions
SET state='approved'
WHERE id=? AND state='pending'

第一次更新影响一行，随后在同一个事务里插入 outbox。重复批准影响零行，不再插入。取消则只允许 pending 进入 cancelled，后来的批准不会将它改成 approved。

本地幂等仍不是外部精确一次#

现在假设另加一个投递器，读取 outbox 后向邮件服务发送。邮件已成功发送，但投递器在写回发送状态前崩溃。下次重试时，这条 outbox 仍可能被再次发送。

这个窗口无法由“本地只有一行”自动消除。需要外部供应商幂等键、结果查询、状态协调或明确的补偿机制。若对端不支持可靠去重，产品只能描述实际能保证的语义，而不能宣称邮件精确一次。

这也是本书借鉴 SAM 幂等章节的方法：区分哪一步可能重复，以及每个标识究竟保护哪一个效果。不要把所有重复问题统称为“加一把锁”。

运行和观察#

在本书目录运行：

python3 examples/mini_host.py
python3 -m unittest discover -s examples -v

测试覆盖两用户线程隔离、入口改绑保留旧线程、重复批准、越权批准、取消后批准和关闭数据库再打开后继续审批。默认演示使用内存数据库；重开实验使用临时目录，不操作你的 Octop 数据。

可以先把 approve 中的 state 条件去掉，预测重复批准会怎样；再去掉线程归属检查，观察负面测试是否失败。只在实验副本修改，不要把破坏后的模型接到真实工具。

实验没有覆盖的能力

没有密码认证、管理员、用户组、HTTP/WS、跨进程任务所有权、外部投递、配额、插件隔离、流式历史和多库恢复。SQLite 重开测试只证明教学模型的待处理记录可重新读取，不证明运行中的模型循环能恢复。

动手检查#

给 outbox 增加一个 sent 字段，然后“发邮件成功后把 sent 设成 1”，能否关闭所有重复发送窗口？

答案提示： 不能。外部成功与本地状态更新之间仍有崩溃窗口。先写 sent 又会在发送前崩溃时漏发。要看对端幂等或查询能力，再设计重试语义，不能用本地字段跨越网络事务边界。

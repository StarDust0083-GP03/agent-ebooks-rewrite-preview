存储与历史：不要寻找唯一数据库

源码快照 2026-10-27 · 约 10 分钟

“聊天丢了”可能有四种含义#

林岚刷新页面后看不到最后一段文字。它可能从未被模型成功产出，也可能产出后未持久化，可能已保存但读取失败，也可能已读出却被前端状态合并覆盖。单看截图，无法判断数据库是不是坏了。

Octop 的状态分散在不同用途的存储中。理解这张表，比先背数据库表名更有用。

类别 保存什么 不应替代什么
控制面 用户、专家、Provider、通道、cron、设置、权限等 图执行现场
checkpoint 线程执行状态与消息上下文 面向用户的完整历史契约
展示历史 / 轨迹 消息投影、工具过程、回合状态 外部动作的最终业务凭证
Agent Memory 提炼、召回和维护的长期信息 原始材料与当前事实核验
工作区 提示文件、技能、输入附件和输出产物 控制面所有配置
知识索引 文档切片与 embedding 聊天状态与权限来源

SQLite 与 PostgreSQL：接口相近，约束仍在#

DatabasePool 协议提供 connect、transaction 和 close。默认 SqlitePool 使用一条共享连接，以 RLock 协调本进程访问，开启外键与 WAL。事务使用 BEGIN IMMEDIATE，提前取得写入相关锁，降低先读后写时遇到快照冲突的风险。

PostgresPool 在边界提供兼容层，仓储里的问号占位符转换成 psycopg 形式。当前 qmark_to_pyformat 是简单替换，源码说明它不理解 SQL 字符串字面量。它适用于受控仓储 SQL，不是一个通用 SQL 方言转换器。

迁移文件有 SQLite 与 PostgreSQL 两套。控制面不负责安装 vector 扩展，记忆的 DDL 也不应混入控制面迁移。ADR 002 特别强调单个活跃 Octop 写入者和不提供 SQLite 到 PG 的自动数据迁移承诺。

把 checkpoint 当历史库会怎样#

运行图保存状态，是为了继续执行、上下文恢复与中断处理。聊天界面希望获得稳定分页、说话人、工具展示、错误状态和导出。这两个读写模式不同，所以项目增加了消息投影及独立历史服务。

当上下文做压缩时，后续模型不一定再读取之前全部内容；用户仍可能需要看原始对话。反过来，历史里存在一段可读文本，也不能证明图能从那里恢复到同一个工具等待点。

因此“备份了聊天导出 JSON”不等于备份可恢复的运行环境；“保留了 checkpoint”也不自动证明用户历史展示完整。

可选 v2 历史为何值得单独看#

快照包含默认关闭的 history_v2。它在本地 history_v2.sqlite 中按段管理历史，用 documents 与 bodies 保存结构和可复用正文。旧段并不批量迁移，新旧格式经兼容读接口统一展示。启用后需要保留对应 required 标记。

它的可靠性取舍很明确：需要保存的流式内容先等待事务提交，再转发给客户端。于是有两种可解释的崩溃窗口：

提交前退出：这条路径不会先把未提交内容发给前端
提交后、发送前退出：历史已有，前端可能还没看到

这不是外部工具精确一次执行保证，也不涵盖上游从未发给采集器的事件。逐事件提交还会增加事务次数及延迟，可靠性收益有成本。

v2 只支持 SQLite 控制面。存在归档文件或标记时，不能假定把开关关掉就能删除文件，或直接退到不认识新格式的旧版本。

三个数据库不等于一个事务#

一轮任务可能写控制面线程信息、历史归档和 Agent checkpoint。这些存储没有因为处于同一进程就自动形成跨库原子事务。

docs/versioned-history.md 明确说明运行中多库备份不保证同一瞬间，并限制涉及 v2 的现有在线恢复与运行时换库。更稳妥的恢复实验，是停机获取完整目录副本，用兼容版本在规定路径恢复，再验证各层引用。

不要只复制一个 octop.db 就宣布已备份全部对话。也不要把不同时间点的主库、归档和工作区随意拼成一个“最新备份”。

数据库表阅读顺序

先看 users、agents、sessions、threads 的身份关系，再看 thread_messages 与 trajectory_events 的投影；随后对照 providers、channels、cron_jobs 和 settings。用户组、角色与分享范围还要看后续迁移。001_initial.sql 是初始结构，不是完整最终 schema。

动手检查#

工作室决定迁移到 PostgreSQL，并同时开启 history_v2，把全部聊天记录放到远程数据库。这个方案哪里不成立？

答案提示： v2 在该快照下要求 SQLite 控制面，且实际使用本地独立归档；知识索引也仍有本地 sidecar。要按数据类别评估迁移，不能用一个控制面选项推导全平台存储行为。

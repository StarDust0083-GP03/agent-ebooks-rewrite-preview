多模态与 Agent：处理更复杂的资料和任务

支付接入规范可能是一份 PDF，关键限制写在时序图上；故障复盘可能放在 PPT，结论依赖趋势图。文本抽取已经丢了图意，再改查询也找不回来。另一类复杂性来自任务：用户要比较多份规范，再定位负责人，可能需要多轮读取。

这两类问题分别属于资料表示和任务控制，不必打包成一个“全能 Agent”才能解决。

图片描述与页面图像检索

Captioning 路线先为图表生成文字描述，再用文本索引检索。优点是能沿用现有流程，代价是描述可能漏掉坐标、单位、图例和细小限定。回答精确数值时，应保留原图并核对，不拿概括文字代替视觉证据。

页面图像检索把页面转换成可检索的视觉表示，命中后交给视觉语言模型读取。ColPali 相关路线属于这一方向。它可以保留版式与视觉关系，也增加页面渲染、图像索引、读取与存储成本。

上游分别提供 Captioning 和 ColPali 示例入口。方法机制和服务封装应区分：调用一个托管检索接口，不意味着本地已经部署完整模型或复现训练过程。

多模态引用要能定位到区域

文本引用可以落到段落，图表引用还需要页码和区域。用户问金额上限，回答若只链接整份几十页文档，仍然难以验证。保存渲染版本、页面 ID、区域坐标及原图关系，才能在界面上高亮依据。

截图中的按钮文案不代表按钮已执行；监控图中的下降也不自动证明某个变更是原因。视觉模型同样需要区分观察与推断。将时序图箭头识别错，可能把回调处理顺序整个颠倒。

Agent 增加了哪些选择

固定流水线由代码决定搜索一次、重排一次、回答一次。Agent 则可以选择工具、追加查询、拆任务或决定继续读取。它扩展了处理复杂问题的空间，也引入提前停止、工具误选和重复搜索。

以负责人问题为例，允许的操作可以仅限于搜索模块、读取归属、搜索团队和读取职责。工具参数采用可校验结构，响应返回稳定来源。不给它退款或发货权限，也不允许模型自行切换用户身份。

上游 Agentic RAG 使用 Contextual AI 托管平台，不能误认为所有能力都在同一套本地 Notebook 环境中。Controllable Agent 则是单独仓库的高级案例，需另查依赖与许可。

停止条件由谁控制

模型认为“还需要查一下”时，应用仍应检查调用次数、时间、费用和权限。模型重复同一查询没有新增证据，就可以终止并返回已知与未知内容。没有明确上限的重规划循环，会把简单查询变成不可预期的任务。

对外展示“规划中”也不能替代进度记录。至少保存每次检索的目标、使用工具、返回 ID 和最终采用的依据，区分“找到了但没用”和“根本没找到”。

哪些任务不值得上 Agent

查单个配置、按字段计数、检查某笔交易状态，通常有更确定的查询或业务接口。让 Agent 先推理该调哪条接口，会额外增加延迟和失误。若任务步骤稳定，普通函数或显式状态机更容易测试。

需要比较十份文档、发现中间缺失资料、反复调整检索路线时，再拿受控 Agent 与固定流程比较。收益应体现在同一任务完成率、证据质量和成本上，而不只是执行轨迹更长。
